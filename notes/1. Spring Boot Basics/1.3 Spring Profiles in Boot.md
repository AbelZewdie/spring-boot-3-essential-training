# Why Profiles?

	Profiles give you the ability to flex your configuration based on the environment that 
	the code is doployed to.

# Multi-Environment Deployments

- Dev Task
- Stage Environment
- Preproduction
- Production

	When running two different production domains.

# Application.yaml

- Spring Boot provides .yaml support natively.
- Allows properties to flex by profile, among other things.
- spring.config.activate.on-profile is key for profile support.
- Other ways to trigger config based on profile.

# Engaging Profiles
How to I tell spring which profile to run?:

- --spring.profiles.active
- Inject via command line or environment
